Build, validate, and monitor a credit model where the data already lives.

Data scientists at consumer lenders often export loan and bureau data to laptops to build default models. This guide keeps the whole lifecycle in Snowflake, from features to validator sign-off, and ends with an early-warning queue portfolio managers can act on.

The business problem

Three handoffs, three places for evidence to get lost

Consumer lending risk teams build, validate, and use default models in different tools. Each handoff costs time and leaves a copy of data behind.

01

Data scientists extract to laptops

Loan and bureau extracts create copies of personal data outside governed storage, and every retrain starts with another extract.

02

Validators rebuild the evidence

Model risk management reviews (for example, under SR 11-7-style expectations) need lineage, out-of-time results, fairness, and drift in one place.

03

Portfolio managers wait

Drift is checked by hand, deployment takes weeks, and early-warning lists arrive without reasons anyone can act on.

● Model validator

The evidence pack, with a first draft written for you

New-to-credit borrowers are underpredicted on this synthetic data set. AI_COMPLETE drafts the "changes from V1 to V2" section from the registry metrics, and the validator edits and owns it.

  • Fairness view is illustrative, by file type
  • Draft text uses only the facts passed in
● Model validator

Promotion is a decision, not a deployment

Approving V2 writes an approval record, moves the CHAMPION alias, and runs the scoring task. Scoring code calls the alias, so nothing is redeployed.

● Portfolio risk manager

A queue with reasons you can act on

Performing accounts whose risk rose fastest in three months. Accounts already 30+ days past due go to collections instead.

● Portfolio risk manager

Decide, with a note that's recorded

Assign outreach, add to the watchlist, or dismiss with a note. In Live mode the decision goes to APP.EW_ACTIONS through bind variables.

Build it with Cortex Code

The training code came from a few plain-language prompts

Data scientists can describe the feature views, label, and comparison they want, and review the code Cortex Code writes, all without leaving governed data. A notebook version for Snowflake Notebooks on Container Runtime is in the repository.

Register a LOAN entity and two Snowflake-managed feature views: static loan terms, and monthly bureau and payment behavior with 3- and 6-month windows.
Build a point-in-time training set at months 3 and 9 on book with a 12-month 90+ DPD label. Train XGBoost, compare on an out-of-time window, and log the best run with a CHAMPION alias.
Score the performing book with model.run for every aliased version, and keep the top three positive SHAP contributions as reason codes.
Create a model monitor on the champion with its training sample as the baseline.
